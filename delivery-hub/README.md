# delivery-hub · 배달앱 통합 대시보드

**배달의민족 · 쿠팡이츠 · 먹깨비** 데이터를 한 화면에서 보는 사장님용 대시보드입니다.

- 기간별 매출: 전체 합계와 플랫폼별
- 수수료 구성: 중개 / 결제 / 배달비 / 부가세, 매출 대비 비중
- 실제 입금되는 **순 정산액**
- 일별 매출 추이, 시간대·요일별 주문
- **통합 리뷰 피드**: 최신순, 낮은 별점 강조, 답글 없는 리뷰만 골라 보기
- **광고비 vs 매출**: 광고비, 매출 대비 광고비, 광고 상품별 클릭당 비용
- 먹깨비 사장님 센터 파일(CSV·XLSX) 업로드

> 지금은 첫 버전(v0.1)이라 **MOCK 모드(샘플 데이터)** 로 동작합니다. 하이픈 계약과 계정 연결을 마치면 실데이터로 바꿀 수 있습니다. 바꾸는 방법은 아래 [실제 연동하려면](#실제-연동하려면)에 있습니다.

---

## 실행 방법

필요한 것: **Node.js 22.18 이상**. 이 버전부터 TypeScript를 빌드 없이 바로 실행할 수 있습니다. 런타임 의존성은 없습니다.

```bash
cd delivery-hub
cp .env.example .env      # 처음 한 번 (기본값 MOCK_MODE=true)
npm start                 # → http://127.0.0.1:8787
```

| 명령 | 설명 |
|---|---|
| `npm start` | 대시보드 서버 실행 |
| `npm run dev` | 파일이 바뀌면 자동으로 재시작 |
| `npm test` | 매핑·집계 테스트 (Node 내장 테스트 러너) |
| `npm install && npm run typecheck` | TypeScript 타입 검사 (개발용, 선택) |

### 먹깨비 파일 넣기
1. 대시보드 맨 아래 **먹깨비 데이터 가져오기**에서 **파일 선택**을 누르고, 사장님 센터에서 받은 주문내역이나 리뷰 파일을 올립니다.
2. 형식은 `samples/mukkebi_orders_sample.csv`, `samples/mukkebi_reviews_sample.csv`를 참고하세요. 열 이름이 조금 달라도 여러 별칭을 인식합니다.
3. 올린 파일은 `data/mukkebi/`에 저장되고 git에는 올라가지 않습니다. 파일이 하나라도 있으면 먹깨비는 샘플 데이터 대신 그 파일을 씁니다.

## 구조

이 저장소의 기존 코드(인스타그램 팔로우 도구, 순수 JS)는 배달 솔루션과 관련이 없습니다. 그래서 독립된 하위 폴더 `delivery-hub/`로 만들었습니다.
스택은 **Node + TypeScript 백엔드**(빌드 단계 없음, 외부 패키지 0개)와 **순수 HTML/JS 대시보드**(SVG 차트를 직접 그림, CDN 없음)입니다. 설치할 게 없어서 인터넷이 없는 매장 PC에서도 바로 돌아갑니다.

```
              ┌──────────────── 브라우저 대시보드 (public/) ────────────────┐
              │  KPI · 플랫폼표 · 일별/시간대/요일 차트 · 광고 · 리뷰 · 업로드 │
              └───────────────▲──────────────────────────────────────────────┘
                              │ GET /api/dashboard   POST /api/mukkebi/import
              ┌───────────────┴───────────── src/server.ts ─────────────────┐
              │  hub.ts: 플랫폼별 병렬 조회 (한 곳이 실패해도 나머지는 표시)   │
              │  aggregate.ts: 순수 함수로 집계 (테스트 대상)                  │
              └──────▲───────────────────▲────────────────────▲─────────────┘
                     │ DeliveryAdapter (단일 인터페이스, adapters/types.ts)
   ┌─────────────────┴───┐  ┌────────────┴──────────┐  ┌──────┴──────────────┐
   │ HyphenBaeminAdapter │  │HyphenCoupangEatsAdapter│  │   MukkebiAdapter    │
   │  *.mapping.ts ←원본  │  │  *.mapping.ts ←원본    │  │ CSV/XLSX → mapping  │
   │  transport: HTTP|mock│  │  transport: HTTP|mock │  │ 파일 | mock(CSV생성)│
   └─────────┬───────────┘  └──────────┬────────────┘  └─────────────────────┘
             └──── 하이픈 API마켓 (계약 후) ┘
```

### 공통 데이터 모델 (`src/model.ts`)
모든 레코드에는 `platform: 'baemin' | 'coupangeats' | 'mukkebi'`가 붙습니다.

| 모델 | 주요 필드 |
|---|---|
| `Store` 매장 | 이름, 카테고리, 수수료율 |
| `Order` 주문 | 주문일시(KST), 상태(완료/취소), 메뉴 요약, 음식금액, 배달팁, 결제(앱/만나서), 배달방식 |
| `SalesRecord` 매출·정산 (일별) | 매출, 배달팁, 중개수수료, 결제수수료, 배달비, 부가세, 기타차감, **입금액**, 정산일 |
| `Review` 리뷰 | 별점, 내용, 메뉴, 사진, **사장님 답글** |
| `MenuItem` 메뉴 | 이름, 분류, 가격, 품절 |
| `AdSpend` 광고비 (일별) | 광고 상품, 금액, 노출, 클릭 |

- 금액은 원 단위 정수, 날짜는 한국시간 기준입니다.
- 정산 주기는 플랫폼마다 다릅니다(주정산, 일정산 등). 비교하기 쉽도록 **매출일 기준 일별**로 맞췄습니다.
- 순 정산액 = 매출 + 배달팁 − (중개수수료 + 결제수수료 + 배달비 + 부가세 + 기타차감)
- 수수료 비중 = 수수료 합계 ÷ (매출 + 배달팁)
- 월 정액 광고(예: 울트라콜)처럼 기간 단위로 받는 광고비는 하루 단위로 나눕니다. 반올림해도 합계는 원금과 같습니다.

### 원본 응답과 매핑을 분리한 이유
하이픈의 실제 필드명은 계약 전에는 공개되지 않습니다. 그래서 플랫폼마다 `*.mapping.ts` 안에 **원본 타입(`Raw*`)과 변환 함수(`map*`)만** 모았습니다.
실제 연동 가이드를 받으면 이 파일만 고치면 됩니다. 어댑터, 집계, 화면은 그대로 둡니다.
MOCK 모드에서도 샘플을 '가정한 원본 응답 모양'으로 먼저 만든 뒤 같은 매핑을 거치기 때문에, 매핑 코드가 늘 실행되고 테스트됩니다.

### 파일 안내
```
delivery-hub/
├─ src/
│  ├─ model.ts                 공통 데이터 모델
│  ├─ adapters/types.ts        DeliveryAdapter 인터페이스
│  ├─ adapters/hyphen/         하이픈 클라이언트, 배민·쿠팡이츠 어댑터, 매핑, mock 전송계층
│  ├─ adapters/mukkebi/        CSV/XLSX 리더, 열 이름 매핑, 어댑터, mock
│  ├─ mock/generator.ts        결정적 샘플 데이터 생성기 (같은 날짜는 항상 같은 값)
│  ├─ aggregate.ts             대시보드 집계 (순수 함수)
│  ├─ hub.ts / config.ts / server.ts
├─ public/                     대시보드 (index.html, app.js, charts.js, style.css)
├─ samples/                    먹깨비 내보내기 샘플 CSV
├─ test/                       매핑·집계·mock 통합 테스트
└─ .env.example                설정 예시 (실제 .env 는 커밋 금지)
```

## 실제 연동하려면

### 1. 배달의민족 · 쿠팡이츠: 하이픈(Hyphen) API마켓

하이픈의 배달 상품은 **'TR시그니처' 상품**입니다. 그래서 **계약과 심사를 거쳐야** 쓸 수 있고, 무료 테스트도 없습니다. ('5건 무료 테스트'는 다른 일부 상품에만 있습니다.)

| 상품 | 이 프로젝트에서 쓰는 API | 아직 안 쓰는 API |
|---|---|---|
| 배달의민족 (14개) | 계정검증, 음식점정보·내 가게, 매출조회, 정산내역, 주문내역, 리뷰, 메뉴, 광고관리 | 통계(주문내역으로 직접 계산), PG매출, 계좌정보, 우리가게NOW, 인근지역매출 |
| 쿠팡이츠 (10개) | 계정검증, 음식점정보·내 가게, 매출·정산, 주문내역, 리뷰, 메뉴 | PG매출, 계좌정보 · **광고 API 없음** |

참고 상품: 배달앱 주문내역 및 리뷰 (요기요·네이버 리뷰 포함 멀티앱), 공유주방 패키지, 하이픈 딜리버리 (배달대행 호출)

**계약 절차**
1. hyphen.im API마켓에서 상품 페이지의 **문의하기**를 눌러 상담을 신청합니다. 문의: help＠hyphen.im / 1600-4173 (2번)
2. 사용 목적, 예상 호출량, 사업자 정보를 내고 **심사**를 받습니다.
3. 계약을 맺은 뒤 **연동 가이드**(엔드포인트, 인증 방식, 요청·응답 필드)와 **API 키**를 받습니다.
4. 코드에서 고칠 곳:
   - `src/adapters/hyphen/client.ts`: Base URL, 인증 헤더, 응답 봉투(`TODO` 주석)
   - `src/adapters/hyphen/baemin.ts`, `coupangeats.ts`: `*_ENDPOINTS` 경로, 요청 필드명
   - `src/adapters/hyphen/*.mapping.ts`: `Raw*` 타입과 `map*` 함수의 실제 필드명
   - 테스트(`test/hyphen-mapping.test.ts`)의 예시 응답을 실제 응답 샘플로 교체
5. `.env`에 아래 값을 넣고 `MOCK_MODE=false`로 바꿔 실행합니다.

**필요한 설정값** (`.env`, 절대 커밋 금지)

| 변수 | 내용 |
|---|---|
| `HYPHEN_BASE_URL` / `HYPHEN_USER_ID` / `HYPHEN_HKEY` | 하이픈 계약 후 발급되는 값 |
| `BAEMIN_LOGIN_ID` / `BAEMIN_LOGIN_PW` | 배민 **사장님 사이트 로그인 계정** |
| `COUPANGEATS_LOGIN_ID` / `COUPANGEATS_LOGIN_PW` | 쿠팡이츠 **사장님 계정** |

### 스크래핑 방식이라 생기는 위험
하이픈의 배달 데이터는 공식 오픈 API가 아닙니다. **사장님 계정으로 대신 로그인해서 화면 데이터를 가져오는(스크래핑) 방식**입니다. 그래서 아래 위험이 있습니다.

- **계정 정보 보안**: 사장님 아이디와 비밀번호를 서버에 보관하고 제3자(하이픈)에게 넘깁니다. 이 프로젝트는 비밀번호를 `.env`에만 두고 화면이나 API 응답으로 내보내지 않습니다. 서버도 기본으로 `127.0.0.1`에서만 열립니다. 클라우드에 올릴 때는 시크릿 매니저, HTTPS, 로그인 보호가 필수입니다.
- **갑자기 끊길 수 있음**: 플랫폼이 화면을 개편하거나, 비밀번호를 바꾸거나, 2단계 인증·캡차가 생기면 조회가 실패합니다. 대시보드는 실패한 플랫폼만 빨간 표시로 알리고 나머지는 계속 보여 줍니다.
- **약관·정책 위험**: 플랫폼 이용약관에서 자동 수집을 제한할 수 있습니다. 계약 시 하이픈이 플랫폼과 어떤 관계인지, 책임 범위가 어떻게 되는지 확인하세요.
- **데이터 지연·차이**: 정산 확정 전 금액은 나중에 바뀔 수 있습니다. 최근 며칠은 '매출조회' 값으로만 채워져 수수료가 0으로 보일 수 있습니다(`TODO` 표시해 둠).
- **호출 비용·제한**: 건당 과금이나 호출 제한이 있을 수 있으니 캐시 주기를 정해야 합니다. (현재는 요청할 때마다 조회합니다.)

### 2. 먹깨비

하이픈 API마켓에 **먹깨비 상품이 없습니다.** 그래서 지금은 **사장님 센터 내보내기 파일(CSV·XLSX)을 올리는 방식**입니다.

- 실제 내보내기 파일의 열 이름을 확인하면 `src/adapters/mukkebi/mapping.ts`의 `ORDER_COLUMNS`, `REVIEW_COLUMNS`에 별칭을 추가하세요.
- 구형 `.xls`는 지원하지 않습니다. 엑셀에서 `.xlsx`나 'CSV UTF-8'로 저장하세요. CP949로 저장된 CSV는 자동으로 다시 해석해 봅니다.

**자동 연동에 필요한 것** (다음 중 하나)
1. **먹깨비(운영사)와 직접 제휴**해서 가맹점 데이터 API나 정기 파일(SFTP 등) 제공을 협의합니다. 공공배달앱이라 지자체를 통해 협의하는 것도 방법입니다.
2. **다른 데이터 중개사**가 먹깨비 상품을 내는지 확인합니다. 내면 그 응답에 맞춰 `MukkebiAdapter`에 전송계층만 추가하면 됩니다.
3. (비권장) 직접 스크래핑: 위 위험을 그대로 지고 유지보수도 직접 해야 합니다.

### 클라우드에서 돌리려면 (다음 단계)
- `HOST=0.0.0.0`으로 바꾸기 **전에** 로그인(인증)을 먼저 붙이세요. 지금은 인증이 없습니다.
- 계정 비밀번호와 API 키는 클라우드 시크릿 매니저에 넣으세요.
- 하이픈 호출 결과를 DB나 캐시에 저장하고, 하루 몇 번 정해진 시각에 동기화하도록 바꾸는 걸 권장합니다(비용·속도·장애 대응).

## 샘플 데이터 안내
수수료율과 배달비는 공개 요금제를 참고한 **예시값**입니다. 배민·쿠팡이츠 중개 7.8%, 결제 3%, 배달비 2,900~3,100원, 먹깨비 중개 2%로 잡았습니다. 실제 계약 조건과 다를 수 있습니다.
매장명 '행복한치킨 본점'과 리뷰도 모두 지어낸 데이터입니다.
